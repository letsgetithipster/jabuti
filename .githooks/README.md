# .githooks/ — hooks do motor, ligados com git config core.hooksPath .githooks. Sem instalação na raiz (o repo oficial, onde se contribui): o pre-commit valida o workspace-exemplo e roda a suíte INTEIRA em todo commit (~90 s); os testes de subprocesso são justamente os que fixam o contrato de saída dos CLIs, então o hook NÃO pula o marker `slow`. Com vault.config.yaml na raiz (a pasta clonada virou a instalação de alguém): pre-commit e pre-push bloqueiam, porque ali o jabuti só muda por git pull, e o post-merge regenera o harness (scripts/gerar_harness.py .) depois de cada pull.
